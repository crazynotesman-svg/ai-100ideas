### D1 REST 载荷形态（血泪教训，务必记住）

`POST /accounts/{acct}/d1/database/{db}/query` **只接受两种形态**：

- `{ sql: "...", params: [...] }` —— 单条（`sql` 也可放多条 `;` 分隔语句）
- `{ batch: [{ sql }, ...] }` —— 批量

**不存在 `bindings`，也不存在 `statements`**：
- 传 `bindings` → `7500 Wrong number of parameter bindings for SQL query.`（占位符有 2 个、绑定 0 个）
- 传 `statements` → `7400 Invalid property: sql => Required | Invalid property: batch => Required`

`scripts/sync.ts` 的 `applyViaRest` 一直写着 `statements`，属**潜伏 bug**——因为 pipeline 实际走 `SYNC_METHOD=wrangler`，这条 REST 路径从未被执行过。已改成 `{ sql: joined }`。`backfill-tags.ts` 现在优先 `batch`、失败自动回退 joined 并记住结果（实测 `batch` 可用）。

## OG PNG 升级（@resvg/resvg-wasm，2026-08-19）

队长确认 Option A/C 上线后，执行「SVG→PNG」升级，让社交卡片真实渲染。

- ❌ **第一坑**：装错包。`@resvg/resvg-js` 是 N-API 原生 `.node` 绑定，**workerd 上跑不了**（部署必崩）。README 写明浏览器/WASM 后端是另一个包 `@resvg/resvg-wasm`。已卸 `resvg-js`、换 `resvg-wasm`。
- ❌ **第二坑**：resvg **只认 TTF/OTF，不认 WOFF**。初版用 @fontsource 的 `inter-*.woff`（`?arraybuffer` 引入），实测 PNG 与无字体完全相同（33770B）→ 文字被静默忽略。验证：用系统 `arial.ttf`（TTF）则文字正常渲染（6136 vs 961B）。结论：必须 TTF。
- ✅ **解决字体**：@fontsource 只发 woff，raw GitHub 路径 404 拿不到 TTF。写 `convert-woff.mjs` 把 WOFF（zlib 压缩的 SFNT）用 `zlib.inflateSync` 还原成 TTF（`inter-400/700.ttf`，`0x00010000` 魔数，渲染验证 PASS：49026 vs 无字体 33770B）。转换脚本与 woff 源文件已清理，只留 TTF 交付物。
- ⚠️ **第三坑**：Vite `?arraybuffer` 在 SSR/Worker 构建里被当成 **URL 字符串**（还带 `?arraybuffer` 后缀），`new Uint8Array(urlString)` 拿到垃圾字节。改用 `?url` → 运行时取字节。
- ✅ **资源加载**：wasm(2.4MB) 与字体(各~68KB) 经 `?url` 产出为 Worker **Assets**；运行时用 **`env.ASSETS.fetch(path)`**（不能用同源 `fetch`：Worker 兼容标志含 `global_fetch_strictly_public`，同源 `fetch('/_astro/*')` 不可靠）。wasm 绝不内联（超脚本体积上限）。`initWasm` 直接收字节。
- `astro check` 0 错误、`astro build` 成功；编译产物确认 `env.ASSETS.fetch(path)` + `initWasm(bytes)`。待推送部署后线上验证 `/api/og` 返回 `image/png` 且体积 >10KB（文字已渲染）。
