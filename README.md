# ai.100ideas.net

Open-source directory of **AI tools & MCP (Model Context Protocol) servers**.

| | |
| --- | --- |
| Framework | [Astro](https://astro.build) 7 (TypeScript, `strict`) — static by default, SSR per route |
| Styling | Tailwind CSS 4 (via `@tailwindcss/vite`) |
| Hosting | Cloudflare Workers / Pages (`@astrojs/cloudflare`) |
| Database | Cloudflare D1 (serverless SQLite) |
| ORM | Drizzle ORM + Drizzle Kit |
| SEO | `@astrojs/sitemap`, canonical URLs, OpenGraph, Twitter Cards, JSON-LD |

## Getting started

```bash
npm install
npm run dev
```

| Command | Description |
| --- | --- |
| `npm run dev` | Local dev server |
| `npm run build` | Production build into `dist/` |
| `npm run preview` | Run the built worker locally with Wrangler |
| `npm run check` | `astro check` — TypeScript + template diagnostics |
| `npm run cf-typegen` | Regenerate `worker-configuration.d.ts` from `wrangler.toml` |
| `npm run db:generate` | Generate SQL migrations from `src/db/schema.ts` |
| `npm run db:migrate:local` | Apply migrations to the local D1 |
| `npm run db:migrate:remote` | Apply migrations to the remote D1 |

## Database

Schema lives in [`src/db/schema.ts`](src/db/schema.ts) and is the source of truth.

```
categories   id, name, slug (unique), description
tools        id, name, slug (unique), one_liner, description_md, github_url,
             website_url, stars, license, category_id -> categories.id,
             alternative_to (JSON array), tech_stack (JSON array),
             is_mcp, is_open_source, created_at, updated_at
submissions  id, url, user_email, status (pending|approved|rejected), created_at
```

Booleans are SQLite `INTEGER` 0/1 and timestamps are unix seconds; Drizzle maps them to
real `boolean` / `Date` values in TypeScript. `alternative_to` and `tech_stack` are TEXT
columns holding JSON array strings such as `'["Notion","Pinecone"]'`, typed as `string[]`.

Generated migrations live in `drizzle/migrations/`. [`schema.sql`](schema.sql) is a flat
snapshot of the whole schema for bootstrapping a fresh database in one shot.

### First-time setup

```bash
# 1. create the database, then paste the returned uuid into wrangler.toml
npx wrangler d1 create ai-100ideas-db

# 2. apply migrations
npm run db:migrate:local     # local miniflare D1
npm run db:migrate:remote    # production D1
```

### Querying

`Astro.locals.runtime` no longer exists in `@astrojs/cloudflare` v13+ — bindings come
from the Workers runtime directly:

```astro
---
import { getDb } from '../db/client';
import { tools } from '../db/schema';
import { desc } from 'drizzle-orm';

export const prerender = false;              // needs a request-time D1 connection

const db = getDb();
const topTools = await db.select().from(tools).orderBy(desc(tools.stars)).limit(20);
---
```

## SEO

[`src/layouts/BaseLayout.astro`](src/layouts/BaseLayout.astro) centralises every head tag:
title/description/keywords, robots directives, canonical URL, OpenGraph, Twitter Cards
and Schema.org JSON-LD. Defaults live in [`src/consts.ts`](src/consts.ts).

```astro
<BaseLayout
  title="Open source alternatives to Notion"
  description="Self-hostable note-taking and knowledge base tools."
  keywords={['notion alternative', 'open source wiki']}
  image="/og/notion-alternatives.png"
  jsonLd={{ '@context': 'https://schema.org', '@type': 'ItemList', itemListElement: [] }}
>
  <h1>...</h1>
</BaseLayout>
```

- `/robots.txt` is generated by `src/pages/robots.txt.ts` and points at the sitemap index.
- `/sitemap-index.xml` is produced at build time; `/admin*` routes are excluded.
- `public/og-default.png` is a placeholder gradient produced by
  `node scripts/generate-og-placeholder.mjs` — replace it with a designed asset or a
  dynamic OG endpoint.

## Known environment issue

The bundled `workerd` binary crashes on this Windows machine
(`structured exception #0xc0000005: access violation`), which breaks both
`wrangler types` and workerd-based prerendering. Two consequences:

1. `astro.config.mjs` sets `prerenderEnvironment: 'node'` so `npm run build` works.
   Remove that line once the [MSVC Redistributable](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)
   is up to date to return to the default (production-identical) workerd prerendering.
2. `worker-configuration.d.ts` is hand-written instead of generated. Re-run
   `npm run cf-typegen` after fixing the runtime to keep it in sync with `wrangler.toml`.

## Phase 2 — ingestion & enrichment pipeline

A Node/TypeScript pipeline ([`scripts/`](scripts/)) that fetches trending open-source AI
repos + MCP servers from GitHub, enriches them with DeepSeek, and upserts them into D1.
It runs daily via GitHub Actions (`.github/workflows/daily-sync.yml`).

```
scripts/
  types.ts          shared types
  util.ts           slugify, SQL escaping, concurrency pool, .env loader
  fetcher.ts        GitHub Search API + README fetch + dedup-friendly topic annotation
  enrich.ts         DeepSeek chat/completions call + JSON parse + deterministic fallback
  sync.ts           builds INSERT…ON CONFLICT upserts; writes to D1 (REST or wrangler)
  run-pipeline.ts   orchestrator (fetch → dedup → enrich → SQL → D1)
  fixtures/         offline sample data for dry runs
```

| Command | Description |
| --- | --- |
| `npm run sync` | Full run: fetch, enrich, upsert into **remote** D1 |
| `npm run sync:dry-run` | Offline-safe preview — writes `scripts/.cache/dry-run.sql`, touches nothing |
| `npm run enrich:test` | Dry run, 3 repos, no DeepSeek (heuristic fallback only) |

### Environment variables

Copy `.env.example` to `.env` (never committed). See the file for the full list. The
secrets used by CI are `DEEPSEEK_API_KEY`, `CLOUDFLARE_API_TOKEN`,
`CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_D1_DATABASE_ID`; `GITHUB_TOKEN` is provided by
GitHub Actions automatically.

### How it works

1. **Fetch** — `fetcher.ts` queries the GitHub Search API across
   `mcp-server, mcp, ai-agent, self-hosted-ai`, keeps repos with ≥ 10 stars, and
   records which topic matched each repo (GitHub's search payload omits `topics`).
2. **Dedup** — `run-pipeline.ts` keeps a `scripts/.cache/seen.json` map of
   `slug → { stars, categorySlug }`. A repo is re-processed only when its star count
   moves by ≥ 50 (`STAR_CHANGE_THRESHOLD`); otherwise it is skipped.
3. **Enrich** — `enrich.ts` calls `deepseek-chat` with `response_format: json_object`
   and validates the result. On missing key / malformed JSON / timeout it falls back to
   a deterministic heuristic so a run never hard-fails.
4. **Sync** — `sync.ts` builds idempotent `INSERT INTO … ON CONFLICT(slug) DO UPDATE`
   statements (categories first, then tools) and applies them. Default transport is the
   **D1 REST API** (`SYNC_METHOD=rest`); set `SYNC_METHOD=wrangler` to instead shell out
   to `npx wrangler d1 execute --remote --file=…`.

### Dry-run without network

For a fully offline preview, point at the fixture:

```bash
GITHUB_FIXTURE=scripts/fixtures/sample-repos.json npm run sync:dry-run
```

Inspect `scripts/.cache/dry-run.sql`, then replay it manually if you like:

```bash
npx wrangler d1 execute ai-100ideas-db --local --file=scripts/.cache/dry-run.sql
```
